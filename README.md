Cloud Engineering Journey

This is where I keep track of what I'm learning as I work through cloud engineering and Linux systems administration on my own, outside of any formal course.

I started with the basics — Linux command line, file permissions, users, processes — before moving into AWS. Since then I've worked through core services like IAM, VPC, EC2, S3, and Lambda/API Gateway, along with the underlying concepts like AWS's global infrastructure (regions, availability zones) and how the different cloud service models (IaaS, PaaS, SaaS) actually differ in practice. I'm currently working toward the AWS Certified Cloud Practitioner exam.

What's in here
Linux basics — permissions, process management, networking commands, firewall and SSH setup, bash scripting and automation
Networking — building a VPC from scratch, public/private subnets, security groups, and deploying web servers inside that setup
Compute — launching and configuring EC2 instances, deploying a web server (Node.js/Nginx) on one
Storage — hosting a static website on S3, working through bucket policies and static site configuration
Serverless — deploying a Lambda function and exposing it through API Gateway as a live HTTP endpoint
Scripts — a small bash toolkit for SSH setup/hardening, cron-based backups, and log parsing
Learning notes — dated entries on what I worked on, what confused me, and how I eventually figured it out

Each project has its own repo with more detail on what was built and how.

Why I'm doing it this way

I'd rather have a record of things I actually built and broke and fixed than just a list of courses I sat through. Early entries here are rougher than later ones — that's kind of the point, it's a record of the process, not a highlight reel.
